# /handover — セッション引継ぎノート

次のセッションが、このセッションで決めたことを**決め直さず**、調べたことを**調べ直さず**に再開できるようにする。ノートは「事実（git の状態）」と「文脈（決めたこと・理由・次の一手）」の 2 層で書く。事実はスクリプトで取り、文脈だけを Claude が書く。

## サブコマンド

| 引数 | 動作 |
|---|---|
| `save`（既定） | ノートを書き出す |
| `load` | 現在のプロジェクトの最新ノートを読み、git の現状と突き合わせてから再開案を示す |
| `list` | 現在のプロジェクトのノート一覧（新しい順に 10 件） |

## 置き場所

`~/.claude/handover/<プロジェクト名>/YYYYMMDD-HHMM.md`

- `<プロジェクト名>` は git のトップレベルのフォルダ名（git 管理外なら作業ディレクトリ名）。スクリプトが決める
- リポジトリの中には置かない（誤ってコミットされるのを防ぐ。プロジェクト側に残したいとユーザーが言ったときだけ、指定の場所に書く）
- compact のたびに、フック `hooks/handover-compact.py` が同じ場所へノートを自動で保存する（見出しに「compact 時に自動保存」と付き、本文は git の状態と compact の要約）。PreCompact で要約にこのスキルのテンプレートの節を含めるよう指示しているので、`load` で手書きのノートと同じように読める

## save の手順

1. 事実を取る（1 回の実行で済ませる）:
   ```bash
   python ~/.claude/skills/handover/scripts/git_snapshot.py --out-dir ~/.claude/handover
   ```
   出力の 1 行目が書き出し先のパス、残りが Markdown の「リポジトリの状態」節。ブランチ・HEAD・未コミットの変更・未 push のコミット・stash を含む
2. 会話を振り返り、下のテンプレートの残りの節を埋めて、1 で示されたパスのファイルに追記する（スクリプトが「リポジトリの状態」節まで書いた状態で作ってある）
3. ユーザーに、ノートのパスと「次の一手」だけを短く伝える

### テンプレート（スクリプトが書いた節の後に追記する）

```markdown
## 目的
（このセッションで何をしようとしていたか。1〜2 文）

## 状況
- 済み: …
- 進行中: …（どこまで進んだか、途中の成果物のパス）
- 未着手: …

## 決めたこと
- <決定> — 理由: <根拠>。却下した案: <案と却下理由>

## 検証の状態
- 実行した検証: `<コマンド>` → 終了コード <n>（最後の編集の後か前かも書く）
- 未検証: …

## はまったこと・試して駄目だったこと
- …（同じ失敗を繰り返さないための記録。エラー文は要点だけ）

## 次の一手
1. 最初にやること（具体的なコマンドかファイル）
2. …

## 最初に読むファイル
- `path` — 理由
```

### 書き方の決まり

- 事実と推測を分ける。確かめていないことは「未確認」と書く
- ユーザーが自分でやると言った操作（`git push` など）は「ユーザー作業」として書き、次のセッションが実行しないようにする
- 機密（トークン・パスワード・本番の接続文字列）はノートに書かない
- 空の節は「なし」と書く（節を消さない。次のセッションが「書き忘れ」と「無い」を区別できるように）

## load の手順

1. `python ~/.claude/skills/handover/scripts/git_snapshot.py --latest` で最新ノートのパスを得て Read する（無ければその旨を伝えて終わる）
2. 同じスクリプトを `--print-only` で実行して git の現状を取り、ノートの「リポジトリの状態」と比べる。ノートの後にコミットや変更が増えていれば、その差を先に報告する（別のセッションや人が触った可能性がある）
3. 「次の一手」を再開案として示し、そのまま進める（不可逆な操作が含まれる場合だけ確認を取る）

## list の手順

`python ~/.claude/skills/handover/scripts/git_snapshot.py --list` の出力をそのまま示す。
