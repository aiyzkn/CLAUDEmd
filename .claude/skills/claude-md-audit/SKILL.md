# /claude-md-audit — 指示の棚卸し

CLAUDE.md は毎回のセッションでコンテキストを消費し、行が増えるほど 1 行あたりの効き目が下がる。モデルが新しくなると、前は必要だった記述が不要になったり、逆効果になったりもする。このスキルは、「**この行を消したら Claude はミスをするか**」を基準に、指示を削る案と、より確実な層へ移す案を出す。

## 対象

| 引数 | 読むもの |
|---|---|
| `global` | `~/.claude/CLAUDE.md` と `@` で取り込んでいるファイル、`~/.claude/rules/*.md`、`~/.claude/skills/*/SKILL.md` のフロントマター、`~/.claude/settings.json` の `permissions` と `hooks`（照合のためだけに読む） |
| `project` | 作業ディレクトリの `CLAUDE.md`・`CLAUDE.local.md`・`.claude/rules/*.md`・`.claude/skills/*/SKILL.md` のフロントマター・`.claude/settings*.json` |
| `all`（既定） | 両方と、現在のプロジェクトの memory（`MEMORY.md` と、その索引が指すファイル） |

スキルの本文は読まない（フロントマターの description だけで、トリガーの重なりを判定する）。

## 手順

1. 対象ファイルの行数と文字数を 1 回のコマンドで出す（`wc -l -m`）。CLAUDE.md の目安は 200 行未満
2. 対象を読み、下の観点で指摘を集める。Hook のスクリプトは中身まで読まず、`settings.json` の登録とスクリプト冒頭の docstring・コメントで、何を強制しているかを判断する
3. 結果を表で示す。**ファイルは編集しない**
4. ユーザーが選んだ案だけを適用する。`settings.json`・Hook・`.mcp.json` に関わる案は、`external-resources.md` の決まりどおり、明示的な指示があるときだけ編集する

## 観点

| 種類 | 見つけ方 | 典型的な案 |
|---|---|---|
| 矛盾 | 2 か所の指示が同じ場面で両立しない（例: 「確認を取る」と「推奨値で進める」の範囲が重なる） | どちらを優先するかを決め、片方を消すか条件を足す |
| 重複 | 同じルールが、言い回しを変えて複数の層にある | 1 か所に寄せる。Hook で強制済みなら、CLAUDE.md には理由を 1 行だけ残すか消す（言い回しが違う重複はモデルを迷わせる） |
| 古い | 存在しないツール・パス・コマンド・廃止した運用を指している | Glob や Grep で実在を確かめてから、消すか直す |
| 既定の振る舞い | 書かなくても Claude がする内容（「丁寧に書く」「バグを直す」など） | 消す |
| 検証できない | 「きれいに」「適切に」など、守れたかを判定できない | 具体的な基準に直すか消す |
| 層が違う | 破ったら事故になる禁止事項が CLAUDE.md にしか無い / 特定のファイルにしか関係しない / 特定の作業でしか使わない手順 | 順に Hook・permissions.deny／`paths` 付きの rules／スキルへ移す |
| 長すぎる | 1 項目が段落になっている、例が多すぎる | 詳細を別のファイルへ移し、参照だけを残す |
| トリガーの重なり | 2 つのスキルの description が同じ依頼文に反応する | description の発動条件を書き分ける |

## 報告の形

```markdown
**状況: 棚卸し完了（編集なし）**
対象: <ファイルと行数>

| # | 種類 | 場所 | 内容 | 案 | 消したらミスするか |
|---|---|---|---|---|---|
| 1 | 重複 | CLAUDE.md:37 と hooks/bash-guard.py | --no-verify の禁止 | CLAUDE.md 側は理由だけ残す | しない（Hook が止める） |

適用する番号を指定してください。
```

「消したらミスするか」が判断できない行は「不明」とし、消さずに残す案にする（迷ったら残す。削りすぎて事故が起きるより、1 行多いほうが安い）。
